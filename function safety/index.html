    功能安全概述

    1. 什么是功能安全

    功能安全（Functional Safety） 属于安全的一部分，针对电子、电气、可编程电子系统(E/E/PE)。 核心目标：防止由设备功能异常、故障导致的危险，而不是防止硬件本身物理损坏。

    简单理解：

    功能安全不是保证设备永远不坏；而是就算硬件/软件发生故障，系统依然要进入安全状态，不对人员、设备、环境造成伤害。

    • 关注点：故障条件下系统行为
    • 对象：控制器、传感器、执行器、软件逻辑、通信链路（如EtherCAT FSoE）
    • 风险思路：风险识别 → 风险评估 → 通过安全措施降低风险到可接受水平

    2. 主流功能安全标准

    2.1 通用基础标准 IEC 61508

    功能安全A类标准，其他行业标准的源头。 - 全称：IEC 61508: Functional safety of electrical/electronic/programmable electronic safety‑related systems - 适用：任意E/E/PE安全相关系统，不限制行业 - 定义核心概念：SIL 安全完整性等级 - 分为多部分：概念、需求、设计、软件、测试、评估等。

    2.2 机械行业 IEC 62061

    • 机械领域专用功能安全标准，基于 IEC 61508
    • 对象：机械设备上电气/电子安全控制系统
    • 同样使用 SIL等级

    2.3 过程工业 IEC 61511

    • 流程工业（化工、炼油）SIS安全仪表系统
    • SIL等级体系。

    2.4 汽车 ISO 26262

    • 道路车辆功能安全
    • 使用 ASIL等级（A‑B‑C‑D），而非SIL。

    2.5 其他相关

    • EN ISO 13849‑1：机械安全，PL性能等级(a‑b‑c‑d‑e) + Category类别，工业自动化非常常用。
    • FSoE (Fail‑Safe over EtherCAT)：EtherCAT安全通信协议，用于实现SIL3安全通讯。

    3. 安全完整性等级 SIL（IEC61508 / IEC62061）

    SIL：Safety Integrity Level 安全完整性等级，衡量安全功能抵抗随机硬件故障、系统性故障的能力。 SIL分为 1‑4 级；SIL4最高，SIL1最低。

    SIL等级 低要求模式 PFDavg（平均危险失效概率） 高要求模式 PFH（每小时危险失效概率） 典型应用场景
    SIL 1 ≥10⁻² ～ ＜10⁻¹ ≥10⁻⁵ ～ ＜10⁻⁴ 低风险辅助安全功能
    SIL 2 ≥10⁻³ ～ ＜10⁻² ≥10⁻⁶ ～ ＜10⁻⁵ 普通设备安全防护
    SIL 3 ≥10⁻⁴ ～ ＜10⁻³ ≥10⁻⁷ ～ ＜10⁻⁶ 工业设备急停、安全门、FSoE通讯
    SIL 4 ≥10⁻⁵ ～ ＜10⁻⁴ ≥10⁻⁸ ～ ＜10⁻⁷ 化工SIS、轨道交通，工业机械极少用到
    • 低要求模式：安全功能很少被触发（化工SIS）
    • 高要求/连续模式：设备运行时安全功能随时待命，工业机械、机器人大多为此模式。

    4. EN ISO 13849‑1 PL 性能等级（机械自动化）

    工业设备、机器人、机床大量使用。 - PL：Performance Level，性能等级：PL a → PL e，PL e最高 - 同时配合 Category（类别 B /1 /2 /3 /4）描述架构。

    PL等级 每小时危险失效概率 PFHd
    PL a < 10⁻⁴
    PL b ≥10⁻⁵ … <10⁻⁴
    PL c ≥10⁻⁶ … <10⁻⁵
    PL d ≥10⁻⁷ … <10⁻⁶
    PL e ≥10⁻⁸ … <10⁻⁷

    参考对应关系（仅参考，不能作为合规依据）： - PL d ≈ SIL2 - PL e ≈ SIL3

    !!! info "倍福 TwinSAFE、FSoE" TwinSAFE、FSoE 通讯组件一般宣称可达到 SIL3 / PL e，整机系统能否达到取决于完整架构、传感器、执行器、逻辑、测试验证。

    5. 汽车功能安全 ASIL（ISO 26262）

    ASIL：Automotive Safety Integrity Level 等级：QM → A → B → C → D；ASIL‑D最高

    • QM：质量管理，不涉及功能安全等级
    • ASIL‑A/B：车身、灯光等较低风险
    • ASIL‑C/D：动力、制动、转向等高风险车载系统

    ASIL只用于汽车，和SIL逻辑相似，但计算方法、开发流程完全独立，不直接套用工业设备。

    6. 几个关键术语小结

    • 安全功能 Safety Function：专门用来降低风险的功能，例如急停、安全门监控、限速。
    • SFF Safe Failure Fraction：安全失效分数，硬件参数。
    • HFT Hardware Fault Tolerance：硬件故障容错，允许系统承受多少个硬件故障仍然保持安全。
    • PFDavg：平均危险失效概率（低要求模式）
    • PFH：每小时危险失效概率（高/连续要求模式）
    • 系统性故障：设计、软件、流程缺陷，不能靠硬件冗余解决，靠流程管控。
    • 随机硬件故障：元器件老化损坏等，可以靠冗余架构缓解。

    7. 简单开发流程简述

    1. 危害分析与风险评估 → 确定需要什么等级（SIL/PL/ASIL）
    2. 定义安全需求（安全功能、安全状态、故障响应）
    3. 系统架构设计（硬件冗余、安全通讯、安全逻辑）
    4. 软硬件开发，遵循对应标准开发规范
    5. 故障分析：FMEA、FTA
    6. 集成、测试、验证确认
    7. 安全手册、文档归档，后期变更管理

    8. 常见误区

    ??? fail "误区1：使用SIL3组件 = 整机就是SIL3" ❌错误。组件SIL等级只是组件能力，整机系统需要：传感器‑逻辑‑执行器完整链路，架构、计算、软件流程、测试全部达标，整机评估后才是系统SIL等级。

    ??? fail "误区2：SIL和PL可以直接等价替换写报告" ❌错误。标准模型不同，只能做技术参考；正式报告要以目标标准原文为准。

    ??? fail "误区3：功能安全等于设备不会坏" ❌错误。允许故障发生；要求故障发生时进入安全状态。
